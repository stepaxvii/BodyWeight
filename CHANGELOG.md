### 🏆 Челленджи (UGC-задачи с календарём)

Социальная фича: любой игрок может создать челлендж "X отжиманий + Y подтягиваний каждый день в течение N дней", присоединиться к открытым, видеть свой и других прогресс на красивом календаре, получить монеты по тиру выполнения.

**Механика:**
- Создатель указывает: название, опционально описание, период (start/end date), 1-5 упражнений с дневной целью каждого
- Логика **AND**: за день засчитывается только если все упражнения выполнены до своих целей
- **Cap по таргету**: если цель 40 отжиманий, в зачёт идут ровно 40 (даже если сделал 60). Лишние повторения по-прежнему дают XP/ачивки/streak — челлендж не альтернативная вселенная, а надстройка
- **Приём закрыт после старта** — опоздуны могут смотреть страницу как зрители, но не присоединяться
- **Tier-награды по % выполнения** (claim-кнопкой, TTL 7 дней с финализации):
  - 100%: 200 монет (tier_perfect)
  - ≥80%: 100 (tier_high)
  - ≥50%: 40 (tier_mid)
  - ≥1%: 10 (tier_participant)
- **Без бонусов автору** — только указание авторства на странице
- **Без хардовых лимитов** — на совести юзеров

**Backend:**
- 4 модели: `Challenge`, `ChallengeExercise`, `ChallengeParticipant`, `ChallengeProgress` (`backend/app/db/models/challenge.py`)
- Миграция `011_add_challenges`
- Сервис `services/challenges.py` — создание, join, `record_progress` (cap по daily_target), статусы upcoming→active→finished, финализация, claim, ранжирование
- Хук в `workout_processor.py` — после расчёта total_xp агрегируем повторения по slug-ам и зовём `record_progress` (best-effort try/except). Дата прогресса = дата завершения тренировки (offline-sync безопасен)
- APScheduler джоб `daily_challenge_lifecycle_job` — 00:10 UTC ежедневно (статусы + финализация)
- 6 эндпоинтов в `/challenges`: `POST /` (создать), `GET /` (каталог с фильтрами status и mine), `GET /{id}` (детали), `POST /{id}/join`, `GET /{id}/calendar` (свой/чужой календарь), `POST /{id}/claim`

**Frontend:**
- Страница `/challenges` — каталог с табами "Идут / Скоро / Завершены / Мои"
- Страница `/challenges/new` — форма создания (выбор упражнений с пикером, дневная цель в естественных единицах: повт./сек/шагов)
- Страница `/challenges/[id]` — детали + сегодняшний прогресс + личный календарь (грид со статусами день: full/partial/none/future) + claim-блок + список участников с %-барами
- Типы и API-методы синхронизированы с backend

### 📢 Скрипт разовой рассылки анонса фичи

- **`backend/scripts/announce_challenges.py`** — одноразовый скрипт-анонс челленджей пользователям
- **Идемпотентен** — повторный запуск не отправит дважды (дедупликация по `(user_id, notification_type='feature_announcement', title)`)
- Каждому юзеру сохраняется in-app уведомление (бейдж колокольчика) и при `notifications_enabled=true` + наличии `telegram_id` отправляется TG push с кнопкой "Открыть приложение"
- Per-user commit после каждого юзера → безопасен при падении посередине (продолжит с того места)
- Флаги: `--dry-run` (счётчики без отправки), `--no-push` (только in-app), `--limit N` (поэтапная раскатка/тест)
- Не привязан к startup — запускается **вручную один раз**: `docker exec bodyweight-api python scripts/announce_challenges.py`
- Helper `send_announcement_push(telegram_id, text)` добавлен в `services/notifications.py` для повторного использования в будущих анонсах

### 🐉 Босс месяца (новая социальная фича)

Главная фича этого релиза — кооперативный рейд против ежемесячного босса. Каждый месяц с 1-го числа активируется уникальный босс с легендой и тематикой сезона. Любая тренировка любого пользователя наносит урон по боссу, а в конце месяца все участники получают монеты по тирам.

- **12 уникальных боссов на год**, по одному на каждый месяц, с авторскими легендами на русском:
  - 🧊 Январь — Ледяной Голем (зима, мерзлота)
  - 🐺 Февраль — Снежный Волк-Альфа (последняя метель)
  - 🪨 Март — Грязевой Колосс (распутица, оттепель)
  - 🍄 Апрель — Грибной Пробуждённый (пробуждение природы)
  - 🌸 Май — Цветочный Спрут (цветение, аллергии)
  - ☀️ Июнь — Солнечный Феникс (летнее солнцестояние)
  - ⛈️ Июль — Громовой Левиафан (летние грозы)
  - 🌾 Август — Жнец Урожая (поля, жатва)
  - 🍂 Сентябрь — Лиственный Кошмар (листопад)
  - 🎃 Октябрь — Тыквенный Король (Хэллоуин)
  - 🌫️ Ноябрь — Туманный Странник (серость)
  - 👑 Декабрь — Зимний Король (праздничное безделье)
- **Механика урона:** damage = итоговый XP тренировки (со всеми множителями), cap 1500 урона на одну тренировку. HP босса: 50 000 (откалибровано под небольшое сообщество).
- **Тиры наград** (победа / просрочка):
  - tier1 (≥1 dmg): 5 / 3 монет
  - tier2 (≥100): 15 / 8 монет
  - tier3 (≥500): 50 / 25 монет
  - tier4 (≥2 500): 150 / 75 монет
  - Топ-10: +200 / +100 монет сверху тира
- **Уведомления:** появление нового босса, проход порогов 50% / 25% / 10% HP, "босс повержен"
- **Награды забираются вручную** кнопкой Claim на странице босса (TTL 7 дней с момента финализации)
- **Финализация:** ежедневный APScheduler-джоб в 00:05 UTC + ленивый fallback при чтении API
- **Пиксель-арт боссов** — 12 уникальных SVG-спрайтов 32×32 в стиле существующих аватаров (`frontend/mini-app/static/sprites/bosses/{slug}.svg`), масштабируются с `image-rendering: pixelated`. Под BossBar — 40px, в hero на странице — 96px, в истории — 48px.
- **Backend:**
  - Модели `MonthlyBoss`, `BossContribution` (`backend/app/db/models/boss.py`)
  - Миграция `009_add_monthly_bosses` + `010_add_boss_image_url` (поле `image_url` с backfill для существующих записей)
  - Сервис `services/boss.py` — спавн, нанесение урона, финализация, claim, ранг игрока
  - Хук в `workout_processor.py` — `boss_deal_damage` после расчёта `total_xp` (best-effort try/except)
  - 5 эндпоинтов в `/boss`: `current`, `leaderboard`, `me`, `history`, `POST /{boss_id}/claim`
  - Контент в `data/bosses.json`
- **Frontend:**
  - Компонент `BossBar.svelte` — компактный HP-бар на главной, кликабелен → `/boss`
  - Страница `/boss` с двумя табами:
    - "Текущий" — emoji босса, легенда, HP-бар, твой урон/ранг/удары, claim-кнопка с подсветкой топ-10, лидерборд топ-10 + твоя позиция если ниже

### ✨ Ходьба как быстрая запись

- **Новое упражнение `walking`** в категории cardio с XP-формулой по шагам
  - Формула: `XP = floor(steps / 50)` — 10 000 шагов = 200 XP, 5 000 = 100 XP
  - 80 минут ходьбы по интенсивности эквивалентны или ценнее 23 минут велосипеда (114 XP)
  - Без оборудования, доступно с 1-го уровня
- **Backend:**
  - `calculate_walking_xp()` в `xp_calculator.py`
  - Поле `steps: int | None` в `ExerciseSetData` (схема и процессор)
  - Спецветка в `workout_processor.py` (хранит шаги в `total_reps`)
  - Валидация в `routes/workouts.py`
- **Frontend:**
  - Кнопка "Ходьба" в главном меню `QuickExerciseModal`
  - Новый шаг `walking-input` с числовым полем шагов (дефолт 10000) и превью XP
  - `calculateWalkingXp()` в `lib/utils/xp.ts`
  - Walking исключён из обычного списка упражнений (как и cycling)
